# 错误分类与端点处置矩阵（P0 验收物）

> 2026-08-26 复核定稿。基于生产代码 `api_pool_server.py`（commit `d5d1f6d`）与 2026-08-25 23:06 部署以来的真实请求样本（631+ 请求、650 成功 / 4 失败 / 多次流式事务失败）交叉验证。
>
> 本阶段边界：只处理生产请求的路由正确性、故障判断、冷却与恢复、缓存保护、fallback 和流式事务完整性。工作由真实故障样本驱动，优先最小确定性修复。不做性能基准、吞吐评估、日志管线重构、路由状态机扩张。

## 核心原则

1. **请求级异常 ≠ 端点级故障**。只有明确、已完成的端点失败证据才触发冷却；单请求超时、探活未完成、流式停滞不升级为端点冻结。
2. **流式事务失败不冻结端点**。停滞/超限属于流事务层，由 `_timeout_abort` 处理，不进入冷却与轮转状态机。
3. **冷却必须幂等**。并发请求的失败是同一故障的重复观测，不延长冷却窗口（`_set_cooldown` 已在冷却中则 return）。
4. **恢复探活不覆盖健康当前端点**，不绕过缓存保护（defer）与手动覆盖。

## 处置状态机小结

**进入冷却**（`_cooldown_until = now + cooldown_minutes×60`）：429（无 Retry-After 时） / 401 / 403 / 5xx(重试用尽) / 连接超时(重试用尽) / 假成功(重试用尽) / 探活失败(30s 短冷却)。
**冻结至手动**：余额不足。
**定时冻结**：配额耗尽（解析 Retry-After / reset_at，默认 5h）。
**不冻结**：单请求饿死、流式事务失败（#10-12）、上下文超限、探活未完成、RPM 本地限流。

**冷却恢复链**（已验证）：冷却过期 → `_cleanup_expired_cooldowns` 后台入队探活（去重：30s 窗口 + inflight）→ 通过 → 清冷却；当前端点开启缓存保护且池活跃 → defer 5min 延迟回切；否则立即回切（不覆盖手动覆盖）。`_reconcile_deferred` 滚动维持/解除 defer。

**切换触发**（显式，非自动）：明确端点故障（冷却）、手动切换、恢复回切、prio99 兜底锁定（全池故障/轮转超 530s）。健康当前端点保持粘性，不被更高优先级端点替换。

## 已知边界与遗留观察项

1. **流式总时长限制**（#11）：默认关闭；仅端点显式配置正数时生效。已有输出后达到上限会发送 `finish_reason: error` 和可见截断原因，不重放部分内容。
2. **手动切换无日志**：`switch_to_endpoint`（L996-1008）全程不写日志，路由指针变更缺审计线索。08-26 15:14 指针跳变排查时无法从日志区分"手动切换"与"其他路径"。小改（补一行 INFO），待授权。
3. **`_transient_count` 瞬态保护计数器**：字段与重置点仍在（L863/L1510/L1561/L1777），但**递增点已不存在**（旧瞬态探活移除时遗留）。当前无害死代码；清理属独立小项，避免本轮扩大范围。
4. **P2 关联**：频繁切换导致 cache 命中率骤降的评估，应基于本矩阵的切换触发条件做参数调优（如 #6/#9 的重试与首包超时平衡），已有端点级首包超时配置入口后调参空间扩大。
